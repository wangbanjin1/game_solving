# VIP 初始未达标比例场景

## 场景矩阵

以当前专项基线“小区 300 人、VIP 占比 20%”为中心。小区人数按相对值上下浮动 20%；VIP 占比按 15%、20%、25% 三档构造。

| 维度 | 取值 |
|---|---|
| 小区总人数 | 240、300、360 |
| VIP 占比 | 15%、20%、25% |
| VIP 初始未达标比例 | 5%、10%、20%、30%、40%、50%、60% |

三个维度做笛卡尔积，共生成 `3 × 3 × 7 = 63` 个场景，累计用户记录数为 `18,900`，不超过配置的 20,000 上限。

“初始未达标”指 VIP 用户初始 MOS 低于该套餐目标 MOS。场景生成时先确定 VIP 总人数，再在全部 VIP 中统一分配达标/未达标档位，因此不会因业务大类分别取整而累积额外误差。实际比例受 VIP 人数整数化约束，输出中同时保存目标比例、实际人数和实际比例。

## 配置与运行

专项配置为：`configs/vip_initial_scenarios_9_21.json`。

```powershell
python -m game_solving generate --config configs/vip_initial_scenarios_9_21.json --output outputs/vip_initial_scenarios_9_21_v2
```

本阶段只生成初始场景，不运行求解。关键输出：

- `solver_inputs.jsonl`：63 个可供后续求解的完整场景。
- `scenes.jsonl`：场景及私有生成审计信息。
- `initial_distribution.jsonl`：每个场景的完整初始分布。
- `initial_distribution.csv`：便于直接检查的跨场景统计表。
- `generation_report.json`：生成成功数、失败数和配额缺口。

CSV 包含小区总人数及其浮动系数、VIP 人数、目标/实际 VIP 占比、VIP 占比相对 20% 基线的偏移量、目标未达标比例、实际未达标人数、实际未达标比例和求解分组数。柱状图及最终页面布局暂不在本阶段生成，后续统一调整可视化时直接读取这些字段。

## 配置约束

- `population.max_users`：单小区人数硬上限，当前为 20,000。
- `population.scenario_grid.max_total_users`：整个场景矩阵累计人数上限，当前为 20,000。
- 启用场景矩阵时必须使用 `quota_mode=specified` 和 `strict_quotas=true`，防止未达标比例被宽松回退改变。
