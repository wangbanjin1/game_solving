## 完整场景运行

逐个执行：

```sh
python -m game_solving run --config configs/default.json --output outputs/final_v2/default
python -m game_solving run --config configs/tiny.json --output outputs/final_v2/tiny
python -m game_solving run --config configs/medium.json --output outputs/final_v2/medium
python -m game_solving run --config configs/large.json --output outputs/final_v2/large
python -m game_solving run --config configs/strict_failure.json --output outputs/final_v2/strict_failure
```

上述路径已存在，重跑时请使用新目录。

| default | 5 × 30 | FEASIBLE_DEGRADED: 5 | 6 | 45343 | 183.12 ms |

四组成功运行退出码均为 0。输出另行核对：所有返回分配无约束违规，总工作量不超配置、完成轮数不超上限、上下行分别不超 120000 kbps。

- default：2 个局部稳定、3 个循环停止；均保留可行降级方案。跨场景加权 MOS 增益合计约 159.8848。
- tiny：两个场景均满足全员基本保障；独立参考均完成离散枚举，状态为 exact_discrete。加权 MOS 增益合计约 3.0104。
- medium：触发 MAX_TOTAL_STEPS，使用 199900/200000 工作量，仍返回可行分配。加权 MOS 增益约 119.2572。这说明复杂候选在当前预算内不一定收敛。
- large：游戏固定配额场景完成千用户处理，MOS 增益为 0，符合固定环境游戏 MOS 与带宽无关的建模。此项验证规模和计数，不验证千用户复杂媒体优化质量。
- strict_failure：退出码 2，生成 0 个成功场景，明确报告 EMPTY_REQUESTED_MOS_BAND，没有把不可达档位伪造成达标数据。
