# 历史 MOS 模拟与欠账补偿

历史生成是可选功能。默认配置关闭，`configs/congestion_exact.json` 提供开启示例。开启后，生成器先生成合法的当前场景，再模拟同一批用户过去若干时段的带宽，计算 MOS，按历史窗口聚合为 `User.history_mos`，供已有角色效用函数使用。

## 配置

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `generation.history.enabled` | `false` | 是否生成历史 |
| `generation.history.periods` | `5` | 正整数，历史时段数 |
| `generation.history.interval_seconds` | `60.0` | 每段持续秒数，必须大于零 |
| `generation.history.bandwidth_multiplier` | `[0.5, 1.5]` | 每次相对于上一模拟分配的倍率采样范围，非负且上限大于零 |
| `utility.history_window_seconds` | `300.0` | 聚合窗口，开启历史时必须大于零 |

历史使用相对时间，当前为 `0`。默认覆盖 `[-300, 0]`。每段 MOS 按其与窗口重叠的秒数加权；例如窗口为 90 秒时，倒数第二段贡献 30 秒，最后一段贡献 60 秒。窗口长于已生成历史时，仅按已有观测时长归一化。

## 历史数据怎样生成

1. 用当前合法分配作为随机游走的初始值，使用独立随机种子生成过去各段的模拟分配。
2. 每段打乱用户及方向的更新顺序，按倍率提出带宽变化，再限制到码率量化网格、媒体上下限、合同、用户限额和小区剩余容量内。
3. 仅调整允许码率自适应的媒体方向。禁止自适应的用户和固定定额业务保持原分配；不合法的提议保留上一分配。
4. 使用原有 MOS 模型计算各段观测，并检查整个时段的上下行容量及用户硬约束。
5. 调用已有 `time_weighted_mos` 聚合历史，写入用户标量。无 MOS 的业务保持 `history_mos=null`。

相同配置和种子可以复现历史。在预算充足时，开关历史不会改变当前采样场景。历史生成与当前场景生成共用 `generation.max_model_evaluations` 工作量预算，耗尽时按原有生成失败流程报告。

## 如何进入效用函数

现有策略以目标 MOS 与历史均值之差计算欠账：

```text
debt = clamp((session_target - history_mos) / 4, 0, debt_cap)
h = (weight + eta_fair * debt) * experience
    - beta_change * abs(experience - current_experience)
```

缺少历史时欠账为零。历史低于目标时，提高获得体验收益的权重；这会影响候选选择和资源协调，但不会覆盖硬约束，也不保证每个欠账用户在每次求解中都得到更多资源。设置 `eta_fair=0` 可以做关闭补偿的对照。

## 输出与验证

`history.jsonl` 每行对应一个场景，包含来源、模型版本、窗口及各段逐用户带宽和 MOS。`scenes.jsonl` 的 `private.history` 保留同样审计；`solver_inputs.jsonl` 只携带求解需要的 `history_mos`。

生成流水线重读历史文件，复算 MOS、检查时段与用户、校验资源约束、重新聚合并比对 `history_mos`。`validation_report.json` 的 `history_observations_validated` 记录校验的用户时段数，包含无 MOS 用户。

独立 `solve` 使用输入中的历史均值，不读取原始历史重新聚合。因此改变窗口后应重新生成数据，或由外部调用方重新聚合后提供新的输入。

测试覆盖随机复现、当前场景隔离、部分时段加权、容量及用户约束、固定用户、共享预算、审计篡改检测、序列化重读、独立求解，以及交换历史均值后补偿分配随之变化的对照实验。

## 建模边界

历史固定当前用户身份、业务、媒体、KQI 和小区容量，只模拟带宽变化。当前分配仅作为合成起点，不代表真实过去的分配轨迹。这个功能可验证历史聚合和欠账补偿是否生效；验证长期公平的动态效果还需要多个控制周期，逐次将实际执行结果回写历史，目前尚未实现该闭环。
